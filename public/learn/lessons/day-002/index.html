Phase 1 · Day 2 · Networks & Web

How computers communicate

Estimated learning time: 8–10 minutes.

Ready to listen.
Core mental model:
A network moves data between devices. The internet connects networks. Names and addresses help traffic reach the right place, and APIs define how software can ask other software to do something.

1. Start with a network

A network is a group of devices that can communicate with one another.

Your home Wi-Fi is a network: phones, televisions, laptops and other devices can connect through networking equipment such as a router.

Yesterday we separated your device from a remote server. Today we are looking at the path that lets those two machines exchange data.

2. The internet is a network of networks

The internet is not one enormous computer and it is not the same thing as the Web.

It is global infrastructure that links many separate networks so data can travel between them.

The Web is one service built on top of the internet. Email, messaging and many other services also use internet infrastructure.

This is a simplification: real internet routing involves many organisations, routers, protocols and possible paths.

3. Data travels in packets

Network data is generally broken into smaller units called packets for transmission.

Packets carry information that networking systems use to move data towards its destination, and protocols define the rules for communication.

You do not need to memorise protocol details yet. The useful idea is that a large message does not usually travel across the internet as one indivisible object.

4. IP addresses help identify destinations

An IP address is an address used by the Internet Protocol so network traffic can be directed to the correct destination.

IPv4 addresses often look like 192.0.2.10, while IPv6 addresses use a longer format.

For now, think of an IP address as a machine-readable network address, but remember that the real relationship between people, devices and public IP addresses can be more complicated because of technologies such as NAT, hosting platforms and load balancing.

5. Domain names make addresses usable for people

Humans are better at remembering names such as sapiverpress.co.uk than changing strings of numbers.

A domain name is a human-readable name used in internet addressing.

The Domain Name System, or DNS, helps translate domain names into technical records that computers can use, commonly including IP addresses.

A useful beginner analogy is a contacts list: you choose a name, and the system helps find the address needed to make the connection.

6. A URL is more specific than a domain

A URL, or Uniform Resource Locator, identifies where a resource can be found and how it should be accessed.

Consider https://example.com/lessons/day-002/.

https is the scheme, example.com is the host or domain portion, and /lessons/day-002/ is the path to a particular resource or location on that site.

So a domain and a URL are not synonyms. A domain is one part that can appear inside a URL.

7. Requests and responses

When software wants something from another system, a common pattern is request → response.

Your browser might request a web page from a server, and the server responds with the data needed to display it.

The details depend on the protocol and application, but this request-and-response model will appear repeatedly throughout the course.

8. Your first mental model of an API

An API, or Application Programming Interface, is an interface that allows software to interact with other software through defined features or rules.

For remote web services, that often means one program sends a structured request to an API endpoint and receives a structured response.

An API is broader than a website or a URL. APIs can exist inside operating systems, browsers, libraries and other software as well as across the internet.

For now, think of an API as a defined software-facing doorway: it specifies what another program is allowed to ask for and how that interaction works.

Why this matters for AI

Many AI applications are distributed systems: the interface on your phone or website may communicate with remote servers that host models or other services.

When you later learn about model APIs, authentication, endpoints, latency and cloud deployment, they will all sit on top of the networking ideas introduced today.

Understanding this also helps you ask an important practical question: where is the computation actually happening?

Key terms

Network — A group of connected devices able to communicate.
Internet — Global infrastructure connecting many networks.
Packet — A unit of data transmitted across a network.
IP address — An address used by Internet Protocol networking.
Domain name — A human-readable name used in internet addressing.
DNS — The system that resolves domain names to technical records used to locate services.
URL — An address identifying a resource and how to access it.
API — A defined interface that allows software to interact with software.
