How software stores information

Estimated learning time: 8–10 minutes.

Ready to listen. Speed: 1.00×.
Core mental model:
Software needs ways to keep information beyond the current moment. Files store data as named resources, databases organise data for reliable querying and updating, and formats such as JSON give structured data a predictable shape.

1. Memory and storage solve different problems

On Day 1, we separated RAM from longer-term storage. That distinction matters to software.

A program can hold a value in memory while it is running, but if that value must survive after the program closes, it usually needs to be written somewhere persistent.

Persistent data might be stored in a file, a database, browser storage, cloud object storage or another storage system.

The important idea is persistence: the information can still exist after the immediate computation has ended.

2. Files are named containers for data

A file is a named collection of data stored by a file system or another storage service.

Files can contain text, images, audio, executable code, structured records or many other kinds of information.

The filename extension, such as .html, .json or .jpg, often indicates a format or convention, but the actual bytes inside the file are what determine its content.

Your Sapiver Learn lessons are HTML files: the browser reads the HTML, CSS and JavaScript and turns them into the lesson interface and behaviour you see.

3. Structured data has an organised shape

Software becomes easier to work with when information follows a predictable structure.

Imagine storing progress as plain text: five correct and finished once. A human can understand it, but software would have to extract the meaning from the sentence.

Structured data separates fields explicitly, such as score, completion state and attempt count.

That means software can access the exact piece of information it needs without interpreting ordinary prose.

4. JSON is a common structured data format

JSON stands for JavaScript Object Notation. It is a text format commonly used to represent structured data.

{
  "completed": true,
  "currentScore": 5,
  "bestScore": 6,
  "attempts": 2
}

The names on the left are keys, and the values on the right contain the associated data.

JSON supports strings, numbers, Booleans, null, arrays and objects. Although its name comes from JavaScript, JSON is used by many programming languages and systems.

5. A database is more than a large file

A database is a system for organising, retrieving and updating data according to a defined model.

Many databases provide features that ordinary files do not provide conveniently, such as efficient queries, indexes, transactions, concurrency controls, access rules and relationships between records.

Relational databases typically organise data into tables with defined relationships, while document databases commonly store record-like documents.

Not every application needs a database. For small, simple datasets, a file or browser storage may be sufficient.

6. Rows, columns and records

In a relational database, a table can be visualised as rows and columns.

A row represents one record, such as one user or one order. Columns define fields such as name, date or status.

This consistent structure lets software query records reliably.

7. Querying means asking stored data a precise question

A query asks a data system to retrieve or manipulate information according to defined criteria.

For example, a database query might ask for all lessons completed after a particular date, or all products whose status is active.

Relational databases commonly use SQL, or Structured Query Language, but not every database uses SQL.

The important idea is that a query is structured communication with the data store.

8. Local storage is useful, but it is not a database server

Your Sapiver Learn lessons use the browser's localStorage feature to remember quiz progress and voice selection.

localStorage stores string values for a website in the browser. To store structured JavaScript data, the lesson converts an object to JSON text with JSON.stringify() and converts it back with JSON.parse().

Browser storage is tied to that browser and site context. Clearing site data can remove it, and it does not automatically synchronise progress across devices.

Worked example: what happens when you answer this quiz

When you choose an answer, JavaScript updates an in-memory progress object.

The lesson serialises that object into JSON text and stores it under a day-specific key in localStorage.

When you revisit the lesson, the page reads the stored string, parses the JSON and rebuilds the visible score and answers.

Why this matters for AI

AI systems depend heavily on data storage and retrieval.

A model may receive conversation history, documents, user settings, evaluation results or retrieved knowledge from storage systems around it.

Later, when we study embeddings and retrieval-augmented generation, you will see a more specialised version of the same pattern: information is stored, indexed, retrieved and supplied to software when needed.

Application memory and model behaviour are separate architectural concerns.
