Phase 1 · Day 5 · Algorithms & Rules

From data to decisions

Estimated learning time: 8–10 minutes.

Ready to listen. Speed: 1.00×.
Core mental model:
An algorithm is a defined procedure for transforming inputs into outputs. In a deterministic system, the same starting state and inputs produce the same result when the rules and relevant conditions are unchanged.

1. An algorithm is a procedure

An algorithm is a defined sequence of steps for solving a problem or completing a task.

Algorithms do not have to involve AI. Sorting a list, calculating tax, validating a password or finding a route can all be expressed algorithmically.

A useful mental model is input → procedure → output.

2. Inputs are what the procedure works on

An input might be a number, a document, a list of records, a user action or another program's output.

The same algorithm can often be reused with different inputs. A VAT calculation, for example, can use the same rule with many different prices.

3. Deterministic means predictable under the same conditions

A deterministic computation produces the same result when it starts from the same state, receives the same inputs and follows the same rules under the same relevant conditions.

Adding 4 + 7 according to ordinary arithmetic gives 11 every time.

Deterministic does not mean simple. A complex program can still be deterministic.

4. Rules can be expressed as conditions

Day 3 introduced conditionals. They are one of the main ways software encodes explicit rules.

if (age >= 18) {
  allowAccess();
} else {
  denyAccess();
}

The program is applying a test to an input value and following the matching branch. The rule can be inspected directly in the code.

5. Order matters

Algorithms are not just collections of rules. The order of operations can change the outcome.

Applying a discount before tax can produce a different result from applying tax before the discount, depending on the rules being used.

Good software therefore needs correct sequencing as well as correct individual operations.

6. State can affect later behaviour

State is information about the current condition of a system that can influence what happens next.

Your quiz has state: which answers were chosen, the current score, the best score and the number of completed attempts.

This is why “same input” is sometimes incomplete. If the starting state differs, the later result can differ too.

7. Randomness can be introduced deliberately

Some programs deliberately use randomness or pseudo-randomness.

A shuffled playlist or test-data generator may be designed to vary across runs.

Many pseudo-random number generators use an initial value called a seed. With the same algorithm and seed, the resulting sequence can often be reproduced.

8. Rule-based software and probabilistic models are different

Traditional rule-based software often behaves deterministically when its inputs, state and environment are controlled.

Many modern AI systems are better described as probabilistic: they model likelihoods and can produce different outputs depending on model settings and runtime behaviour.

This does not mean ordinary code is always reliable or AI is always unreliable. They fail in different ways and require different controls.

Worked example: a hard rule around an AI system

Suppose an application uses an AI model to draft a customer response.

The model can generate the draft, but ordinary code can enforce a non-negotiable rule: nothing is sent unless a human approval flag is present.

This combines flexible model behaviour with deterministic release control.

Why this matters for AI

AI applications are usually combinations of models, data, deterministic code and human decisions.

Understanding algorithms and rules lets you separate what the model is allowed to judge from what the software should guarantee.

That distinction becomes important later in agents, automation, evaluation and safety controls.

Key terms

AlgorithmA defined procedure for completing a task.
InputInformation supplied to a procedure or system.
OutputThe result produced by a procedure or system.
DeterministicProducing the same result when the relevant starting conditions are the same.
StateStored information describing the current condition of a system.
RuleAn explicit condition or instruction governing behaviour.
Pseudo-randomGenerated algorithmically to behave like randomness for practical purposes.
ProbabilisticBased on likelihoods rather than one guaranteed output path.
