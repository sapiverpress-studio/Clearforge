Phase 1 · Day 8 · Large Language Models

How large language models generate text

Estimated learning time: 8–10 minutes.

Ready to listen. Speed: 1.00×.
Core mental model:
A large language model receives text as tokens, processes them through a trained transformer network, predicts a probability distribution for the next token, selects one, then repeats. Fluent output is generated token by token; fluency does not prove factual accuracy.

1. A language model predicts sequences

A language model learns statistical patterns in sequences of language.

Modern large language models are trained to predict tokens from context. During generation they repeatedly predict a next token, append it, then predict again.

This high-level description hides a great deal of neural-network computation, but it is the right mental model.

2. Text becomes tokens

Language models process units called tokens.

A token may be a whole word, part of a word, punctuation, whitespace or another fragment, depending on the tokenizer.

This matters because model limits and usage are generally measured in tokens rather than ordinary word counts.

3. Tokens become numerical representations

Tokens are mapped to numerical vectors called embeddings.

These vectors give the neural network a mathematical representation it can transform.

Later we will study embeddings separately because related vector representations are also used in semantic search and retrieval systems.

4. Transformers use attention

Most modern large language models use a neural-network architecture called a transformer.

A central mechanism is attention, which lets a layer calculate how strongly different token positions should influence one another during the current computation.

This is a simplification: transformer layers contain several components besides attention.

5. Context is what the model can use now

The context is the token sequence available to the model during a generation.

It can include instructions, conversation history, user messages, tool results, retrieved documents and generated tokens, depending on the application.

The maximum amount the model can consider at once is often called its context window.

A model does not automatically have access to every past conversation or file; relevant information must be supplied by the application or another mechanism.

6. The model scores possible next tokens

At each step, the model calculates scores for possible next tokens and converts them into a probability distribution.

Generation settings can affect how predictable or varied token selection is.

This is one reason the same prompt can produce different wording on separate runs.

7. Generation repeats

Once a token is selected, it becomes part of the sequence and the model predicts again.

Input text
Tokenise
Transformer pass
Choose token
Repeat

The loop stops when the model or application reaches a stopping condition.

8. Fluency and truth are different

A language model is trained to produce plausible continuations based on patterns in training data and current context.

That objective does not guarantee that every generated claim is true.

A model can produce confident, fluent text containing an incorrect fact, invented citation or faulty inference.

Factual tasks therefore often need evidence, retrieval, tools, validation or human review.

9. The model is not the whole application

Ordinary software decides which model to call, what context to send, which tools are available, what gets stored and which actions are permitted.

This distinction becomes important when we later study APIs and agents.

Worked example: answering a question

Suppose you ask an AI assistant, “Why does rain form?”

The application assembles instructions and relevant context, converts the text into tokens and sends them to the language model.

The transformer processes the sequence, predicts the next token, selects one, adds it to the sequence and repeats until the answer ends.

If the application has search or retrieval tools, it can first gather evidence and include it in the model's context.

Why this matters

This model explains why wording can vary, why long conversations are constrained by finite context and why fluent answers can still be wrong.

It also explains why prompting matters: instructions and supplied evidence become part of the context used to generate the next tokens.

Key terms

Language modelA model trained to represent and predict language sequences.
TokenA unit of text processed by the model.
TokenizerThe system that converts text to and from tokens.
EmbeddingA numerical vector representation.
TransformerA neural-network architecture widely used for modern language models.
AttentionA mechanism for combining information across token positions.
Context windowThe maximum token sequence available to a model for an operation.
Next-token predictionPredicting which token should follow the current sequence.
