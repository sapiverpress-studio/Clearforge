Embeddings and semantic similarity

Estimated learning time: 8–10 minutes.

Ready to listen. Speed: 1.00×.
Core mental model:
An embedding converts an item such as text into a vector of numbers. Items with similar meaning can end up near one another in that vector space, which lets software search by semantic similarity rather than exact wording alone.

1. An embedding is a numerical representation

An embedding is a vector: an ordered list of numbers produced by a model to represent an input.

The input might be text, an image, audio or another kind of data, depending on the model.

The individual numbers are usually not meaningful to a human on their own. Their usefulness comes from the geometry of the whole vector space.

2. Similar meaning can produce nearby vectors

Embedding models are trained so that useful relationships in the input are reflected in vector relationships.

For text embeddings, sentences with similar meaning often have vectors that are closer together than unrelated sentences.

This is called semantic similarity: comparing meaning rather than just matching exact words.

3. Semantic search differs from keyword search

A keyword search looks for matching words or terms.

Semantic search can retrieve relevant text even when the wording differs.

For example, car will not start might be semantically close to a document about engine fails to turn over, even though the phrases are not identical.

Many real search systems combine semantic and keyword methods rather than choosing only one.

4. Similarity needs a mathematical measure

Once two items have embedding vectors, software needs a way to compare them.

One common measure is cosine similarity, which compares the angle between vectors.

Other systems may use dot product or distance measures such as Euclidean distance, depending on the model and index design.

The important point is that the comparison happens numerically in vector space.

5. Documents are often split into chunks

Long documents are commonly divided into smaller chunks before embeddings are created.

This lets retrieval return the most relevant section rather than an entire large document.

Chunk size is a design decision: chunks that are too small can lose context, while chunks that are too large can mix several topics and reduce precision.

6. A vector index makes similarity search efficient

Applications may need to compare a query against thousands or millions of stored embeddings.

A vector index organises vectors so nearby or similar items can be found efficiently.

Some systems use specialised vector databases, while ordinary databases increasingly provide vector-search features too.

The important job is to store vectors and retrieve the nearest useful matches.

7. Similarity does not prove correctness

Similarity means related, not necessarily true, current or authoritative.

A semantically similar document can still be outdated, incorrect or unsuitable for the user's question.

Good retrieval systems therefore also consider metadata, permissions, source quality, freshness and other filters where relevant.

8. Embeddings are useful before an LLM generates anything

Embedding search is usually a retrieval step, not text generation.

The system can embed a user's query, search stored vectors, select relevant chunks and then pass those chunks into a language model as context.

This is one of the foundations of retrieval-augmented generation, or RAG, which we will cover next.

Worked example: searching a support knowledge base

Imagine a company has hundreds of support articles.

Split articles into chunks
Create embeddings
Store vectors
Embed user query
Return nearest chunks

A user asks, “Why does my account keep signing me out?” The system creates an embedding for that question and searches for nearby article chunks.

It might retrieve a passage about session expiry even if the exact phrase signing me out never appears in the article.

The application can show those passages directly or supply them to a language model as evidence for an answer.

Why this matters

Embeddings connect machine learning to practical information retrieval.

They let software compare meaning numerically and are used in semantic search, recommendations, clustering and retrieval systems.

For AI applications, the crucial pattern is simple: retrieve useful information first, then give the model better context.

Key terms

VectorAn ordered list of numbers used as a mathematical representation.
Semantic similaritySimilarity based on meaning rather than exact wording alone.
Cosine similarityA common measure based on the angle between vectors.
ChunkA smaller section of a larger document used for indexing or retrieval.

RetrievalThe process of finding information relevant to a query.
