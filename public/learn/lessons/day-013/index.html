Phase 1 · Day 13 · Agents & Tool Use

How AI agents use tools and take actions

Estimated learning time: 8–10 minutes.

Ready to listen. Speed: 1.00×.
Core mental model:
An AI agent is not simply a chatbot with a longer prompt. It is a system where a model can choose among permitted tools, observe results, update working state and continue across multiple steps until a stopping condition is reached.

1. An agent is a system, not just a model

A language model can generate text, but an agent adds a control loop around the model.

The application gives the model instructions, a set of available tools and working state. The model can decide what to do next, call a tool, inspect the result and continue.

The model proposes or selects actions; ordinary software defines what tools exist, how calls execute and what limits apply.

2. Tools turn model decisions into operations

A tool is a capability the agent can invoke through a defined interface.

Examples include searching the web, reading a database record, sending an email, creating a calendar event, running code or updating a file.

The model sees a tool description and input schema; application code performs the actual operation.

3. The agent loop alternates decisions and observations

A simplified loop is: inspect the current context, choose the next step, call a tool if needed, receive the result, then decide again.

Goal
Choose step
Call tool
Observe result
Update state
Stop or continue

The loop can run once or many times. More steps do not automatically mean better work.

4. State carries information between steps

An agent needs state so later steps can use information gathered earlier.

State can include conversation history, tool results, task progress, temporary variables or retrieved evidence.

State does not have to mean permanent memory. Some state lasts only for one run; other state may be deliberately stored.

5. Permissions should be narrower than capability

A tool may technically support many actions, but an agent should receive only the permissions needed for its job.

For example, a support agent might read an order and draft a response without being allowed to issue refunds automatically.

This follows least privilege: give the system the minimum access necessary for the task.

6. Guardrails and approvals constrain risky actions

Guardrails validate or restrict inputs, outputs or actions.

A consequential action may also require explicit human approval before the tool call executes.

An agent might prepare a refund request but pause before submission, or draft an email but require approval before sending.

7. Stopping rules prevent uncontrolled loops

An agent needs a clear reason to stop.

Stopping conditions can include completion, a maximum number of steps, a cost or time limit, repeated failure, missing permissions or the need for human input.

Without stopping rules, an agent can waste tokens, repeat actions or keep trying a task it cannot complete.

8. Handoffs and routing divide work

Some systems use specialised agents or routes rather than one agent doing everything.

A triage component might send billing, technical support and account requests to different specialists.

This can improve clarity and permissions, but multi-agent design also adds orchestration complexity and should solve a real separation problem.

9. Tracing makes multi-step behaviour inspectable

Agent failures can involve a sequence of model decisions and tool calls.

Tracing records those steps so developers can inspect which tool was selected, what arguments were sent, what result came back and how the next decision followed.

This supports debugging, evaluation, reliability and cost control.

Worked example: handling a damaged-order request

A customer says, “My parcel arrived damaged. Can you replace it?”

The agent identifies the order, uses an order lookup tool and checks the replacement policy.

If policy permits a replacement, it can prepare the request. The system can require approval before the final consequential action.

If the order cannot be found, the agent should stop rather than inventing one and explain what information is missing.

Why this matters

Agents move AI from generating content toward operating workflows.

That makes permissions, tool schemas, approvals, stopping conditions, tracing and evaluation more important, not less.

The model is only one component inside the control system.

Key terms

AgentA system in which a model can choose actions and tools across multiple steps.
ToolA defined capability the agent can invoke through software.
Agent loopThe repeated cycle of deciding, acting, observing and deciding again.
StateInformation carried between steps of a task.
GuardrailA check that constrains or validates inputs, outputs or actions.
ApprovalA required human decision before a consequential action proceeds.
HandoffA transfer of control from one agent or route to another.
TraceA recorded sequence of model decisions, tool calls and results.
